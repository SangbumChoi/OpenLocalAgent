Fixed held-out cases span computer use, code, web, app actions, and abstention. Results include p50/p90/p95/p99 TTFA, exact-action accuracy, schema validity, and the fraction of correct actions delivered before each deadline. Structured mode emits no tokens. Raw mode selects from final-token logits until EOS or the token cap. Candidate-trie mode masks each next-token choice against a trie of complete prompt-grounded schema-valid actions; it is still iterative autoregressive decoding, not the structured head. Both AR controls require the final lineage-bound cached bundle, run one prefill, then rebind present tensors into one-token decode calls. Their JSON records report decode_cache: true and identify logits as the decision source; exported next_token is a compatibility argmax cross-check. For the structured policy, fixed-compute controls append whitespace after the complete natural prompt, run the full graph, and dispatch from the natural assistant-marker state; this preserves the SFT feature contract while recording both natural and compute token counts. Autoregressive controls retain the older pre-assistant whitespace stress condition because generation consumes the final prefix state. The largest target is 1,536 so a 2,048-token model still has room for the declared autoregressive output cap.
